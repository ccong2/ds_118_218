Data and Disputes

Today we will explore the COMPAS (Correctional Offender Management Profiling for Alternative Sanctions) model. It was a popular commercial algorithm used by judges and parole officers for scoring criminal defendant’s likelihood of reoffending (recidivism). ProPublica has shown that the algorithm is biased in favor of white defendants, and against black inmates, based on a two-year follow-up study (i.e who actually committed crimes or violent crimes after 2 years). The pattern of mistakes across racial groups in this dataset is notable.

This dataset is frequently used to study machine learning bias and is now readily available through mlr3fairness package.

data("compas", package = "mlr3fairness")

If you check out ?mlr3fairness::compas, you will see its documentation including variable explanations and data processing notes. The data includes basic demographics (age, race, sex), and a few variables about prior offense history, such as charge degree (c_charge_degree: F for Felony, M for Misdemeanor), and length_of_stay.

The decile_score column is the COMPAS model’s estimated risk of recidivism (1–10). The score_text column puts these into text categories: Low (1–4), Medium (5–7), and High (8–10) risk.

Then there is the two_year_recid column. This is based on Propublica’s follow-up. It’s a binary variable indicate whether defendant was actually rearrested (1) and not rearrested (0) within two years.

Evaluate COMPAS

How did COMPAS come up with the decile_score is not known (a proprietary algorithm), but we can treat these scores as a “predicted label”, and the two_year_recid as the “actual label” to evaluate this COMPAS’s performance.

To clarify our analysis, we’ll create two new columns. The first, predicted, will be “Yes” if decile_score is greater than 5, and “No” if otherwise. The second, actual, will be “Yes” if two_year_recid is 1, and “No” if it is 0.

compas <- compas |>
  mutate(
    predicted = case_when(
      decile_score > 5  ~ "yes",
      decile_score <= 5 ~ "no"
    ),
    actual = factor(
      two_year_recid,
      levels = c(0, 1),
      labels = c("no", "yes")
    )
  )

Model Accuracy

How well does COMPAS predict reoffending? One way to measure it is by checking the model’s accuracy. Since this is a classification problem with “Yes” or “No” outcomes, accuracy is defined as the proportion of correct predictions: both when the model predicts reoffending and the person does reoffend, and when it predicts no reoffending and the person does not.

In other words, accuracy tells us how often the model is correct overall.

correct_predictions <- compas |>
  filter(
    (predicted == "yes" & actual == "yes") |
    (predicted == "no" & actual == "no")
)

accuracy <- nrow(correct_predictions) / nrow(compas)
accuracy
[1] 0.6642903

In our case, the accuracy of the COMPAS model is about 0.66, meaning it makes the correct prediction 66% of the time. It’s not particularly high, but it’s better than random guessing (50%).

Confusion Matrix

Accuracy doesn’t show in what way a model makes mistakes. It treats a false positive (predicting someone will reoffend when they won’t) the same as a false negative (predicting someone won’t reoffend when they will). In practice, these errors can have very different implications.

Confusion matrix breaks down the types of correct and incorrect predictions:

# True Positive: predicted recidivism, actually recidivated
TP <- sum(compas$predicted == "yes" & compas$actual == "yes")  

# True Negative: predicted no recidivism, didn't recidivate
TN <- sum(compas$predicted == "no" & compas$actual == "no")  

# False Positive: predicted recidivism, didn't recidivate
FP <- sum(compas$predicted == "yes" & compas$actual == "no")  

# False Negative: predicted no recidivism, actually recidivated
FN <- sum(compas$predicted == "no" & compas$actual == "yes")  

# Create a matrix manually
conf_matrix <- matrix(c(TN, FN, FP, TP),
                      nrow = 2, byrow = TRUE,
                      dimnames = list(Prediction = c("N", "P"),
                                      Reference = c("N", "P")))
conf_matrix
          Reference
Prediction    N    P
         N 2647 1356
         P  716 1453

This matrix reads:

           Reference (Actual)
Prediction    no     yes
         -----------------
      no  |   TN     FN
      yes |   FP     TP

A perfect classifier would only have non-zero values on it’s main diagonal (TN and TP).

To put this result in our context, in the “Actual No” column, there are (2647+716=3363) people who actually did not reoffend. Among them, 716 were misclassified. In other words, about (716/3363 = 21%) non-reoffenders were flagged as high risk. This is the False Positive Rate (FPR): the proportion of non-reoffenders incorrectly predicted as reoffenders.

Breaking it down by racial groups

If we take a closer look and break down the confusion matrix by racial groups, we will see that the model’s errors are not evenly distributed.

The analysis by Propublica has this quote:

“Black defendants were often predicted to be at a higher risk of recidivism than they actually were. Our analysis found that black defendants who did not recidivate over a two-year period were nearly twice as likely to be misclassified as higher risk compared to their white counterparts”

This means the FPR (predicting someone will reoffend when they won’t) is higher for Black defendants compared to white defendants.

We’ll now reproduce this analysis ourselves.

To make the process easier and reusable, we’ll define a function that generates a confusion matrix for any specified race.

Note: Writing your own function can be a bit less intuitive, but it works like outlining the entire process using “placeholder” variables. After the process is built, you use the function by providing actual variables as inputs to replace those placeholders.

# Define a function to calculate confusion matrix cells by race
confusion_by_race <- function(df, race_name) {
  df_race <- df |> filter(race == race_name)
  
  TP <- sum(df_race$predicted == "yes" & df_race$actual == "yes")
  TN <- sum(df_race$predicted == "no" & df_race$actual == "no")
  FP <- sum(df_race$predicted == "yes" & df_race$actual == "no")
  FN <- sum(df_race$predicted == "no" & df_race$actual == "yes")
  
  return(c(TP = TP, TN = TN, FP = FP, FN = FN))
}

Then calculate the confusion matrix for Black and White population, separately.

# Remove other objects from the workspace to start fresh
rm(list = setdiff(ls(), c("compas", "confusion_by_race")))

# Calculate for Black affenders
b_vals <- confusion_by_race(compas, "African-American")
b_fpr <- b_vals["FP"]/(b_vals["FP"]+b_vals["TN"])

# Calculate for White affenders
w_vals <- confusion_by_race(compas, "Caucasian")
w_fpr <- w_vals["FP"]/(w_vals["FP"]+ w_vals["TN"])

# Print our results
str_glue(
  "FPR: \n",
  "Black defendants: {round(b_fpr*100)}% \n",
  "White defendants: {round(w_fpr*100)}%")
FPR: 
Black defendants: 31% 
White defendants: 14%

This aligns with the Propublic result. Black defendants who did not recidivate over a two-year period were nearly twice as likely to be misclassified as higher risk than their White counterparts.

Propublica has another quote:

“White defendants were often predicted to be less risky than they were. Our analysis found that white defendants who re-offended within the next two years were mistakenly labeled low risk almost twice as often as black re-offenders”

This points to another type of model error: False Negative Rate (FNR). It tells us, among all people who actually reoffended (the “Actual Yes” column), how many were missed by the model (predicted as No).

# Calculate FNR for Black reaffenders
b_fnr <- b_vals["FN"]/(b_vals["FN"]+b_vals["TP"]) 

# Calculate for White reaffenders
w_fnr <- w_vals["FN"]/(w_vals["FN"]+ w_vals["TP"])

# Print our results
str_glue(
  "FNR: \n",
  "Black defendants: {round(b_fnr*100)}% \n",
  "White defendants: {round(w_fnr*100)}%")
FNR: 
Black defendants: 38% 
White defendants: 61%

Similar to Propublica’s result, White defendants are almost twice as likely to be incorrectly classify as low-risk compared to Black defendants.

Such kind of pattern is generally referred to as disparate impact: when a decision-making process seems neutral on the surface but still results in unequal outcomes for certain groups. In this case, the COMPAS model tends to over-predict risk for Black defendants and under-predict for White defendants, leading to unequal results.

Does this mean the COMPAS model is simply problematic? To explore this further, let’s try building our own prediction model and see how it performs.

Logistic classification model

Logistic regression is a supervised learning method that uses a linear combination of variables to predict the probability of a “yes” outcome. When you turn those probabilities into actual labels like “yes” or “no,” it becomes a classification model. The model is based on a straight-line equation, so the line separating the two classes is also straight.

Variable selection notes

Choosing which variables to include in a model is a critical challenge in algorithmic decision-making. Steif’s book highlights an important tension around using predictors like race and prior_count.

If we include race in a Multiple Linear Regression (MLR), for example, the results table will show the effect of the race variable, which might read: “Being race X increases predicted recidivism by 0.2”. This kind of output is problematic. It means the model will consistently add 0.2 for defendants of race X. In other words, it encodes bias into the predictions.

Even if race is not explicitly included as a predictor, variables like priors_count can still reflect historical biases in policing that are correlated with race, leading algorithms to make consistently less accurate predictions for certain socioeconomic groups. Predictors like this, such as redlining districts, eviction history, etc., should be used with caution.

Model Building

We’ll now repeat the modeling workflow you’ve used in previous sessions.

modeldata <- compas |> 
  select(actual, age, sex, race, c_charge_degree, priors_count, length_of_stay)

set.seed(24)
train_index <- createDataPartition(
  y = modeldata$actual,
  p = 0.7,
  list = FALSE
)

train_data <- modeldata[train_index, ]
test_data  <- modeldata[-train_index, ]

In the train() function, set method = "glm" to specify that we’re using a generalized linear model. family = "binomial" indicates that the outcome variable is binary.

Note: Model comparison tests (such as ANOVA and AIC) will show that priors_count significantly improves model performance. So given our available predictors, we will include priors_count in our model, while excluding race.

logit_model <- train(
  actual ~ . - race,  # The "-" sign is to remove one specific variable from all (".") predictors.
  data = train_data,
  method = "glm",        
  family = "binomial"
)

Although our model has slightly better accuracy than COMPAS, it produces very similar results and shows the same level of disparities.

Part of the reason models generate biased result is that they learns from historically biased data. We can’t undo the historical patterns that shaped the data, and we often can’t completely avoid using variables that carry implicit bias, especially when they carry predictive power. Recognizing this challenge is broadly referred to as fairness-aware modeling.

But there are still a range of strategies we can apply: understanding the data context, being critical about variables that may act as proxies for protected characteristics, and applying fairness techniques in the decision-making process to correct potential harm. We’ll try to improve our logistic classification model using some of these ideas.

Adjust Classification Thresholds

In logistic regression, the model doesn’t directly predict a “yes” or “no” outcome. It predicts a probability between 0 and 1 that an observation belongs to the positive class. A final classification decision still needs to be made. By default, the threshold is set at 0.5, meaning if the predicted probability is greater than 0.5, the case is classified as “yes”, otherwise “no”.

By adding type = "prob" in the predict function, we will get the results of predicted probabilities instead of class labels. This lets us adjust the decision threshold, which means, if we lower the decision threshold, the model is more likely to predict “yes”.

Changing the threshold affects how predictions fall into true or false positives and negatives, which in turn impacts error rates and fairness.

# This is the probability result
pred_probs <- predict(logit_model, newdata = test_data, type = "prob")

Now let’s try to set different classification thresholds for different groups!

# Attach pred_probs to the test data
test_pred <- 
  test_data |> 
  mutate(pred_prob = pred_probs$yes)

# Define separate thresholds we want to use
thresholds <- list(
  African_American = 0.6,
  Caucasian = 0.5
)

# Create a new "predicted" column based on group-specific thresholds.
# For African-American and Caucasian individuals, apply separate thresholds.
# For all others, use the default threshold of 0.5.
test_pred <- test_pred |>
  mutate(predicted = case_when(
    race == "African-American" & pred_prob > thresholds$African_American ~ "yes",
    race == "African-American" & pred_prob <= thresholds$African_American ~ "no",
    race == "Caucasian" & pred_prob > thresholds$Caucasian ~ "yes",
    race == "Caucasian" & pred_prob <= thresholds$Caucasian ~ "no",
    pred_prob > 0.5 ~ "yes",
    TRUE ~ "no"
  ))

Now that we have applied group-specific thresholds, we can calculate and compare performance metrics again: FPR, FNR and Accuracy, for African-American and Caucasian defendants, separately.

# three metrics, FNR, FPR and Accuracy for both race
b_vals <- confusion_by_race(test_pred, "African-American")
b_fpr <- b_vals["FP"] / (b_vals["FP"] + b_vals["TN"])
b_fnr <- b_vals["FN"] / (b_vals["FN"] + b_vals["TP"])
b_acc <- (b_vals["TP"] + b_vals["TN"]) / sum(b_vals)

w_vals <- confusion_by_race(test_pred, "Caucasian")

Today’s analysis is built on Chapter 7 of Public Policy Analysis. In this chapter, the author introduced a few guildlines for an “equity threshold”,

  • Minimize differences in False Positive Rates (FPR) and False Negative Rates (FNR) between racial groups, while keeping both rates relatively low.
  • Minimize differences in Accuracy rates between racial groups, while keeping the overall Accuracy high.

Lab Report

Your goal is to explore multiple possible threshold combinations to see whether some produce better fairness, better accuracy, or a better balance of both.
